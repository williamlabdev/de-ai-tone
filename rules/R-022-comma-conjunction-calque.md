# R-022 逗號＋而黏句 / Comma-conjunction calque

## 現象

用逗號把兩個本該分開的完整子句黏在一起，再用「而」承接，把英文「, and」「, while」「, but」那種逗號＋對等連接詞的句法直接搬進中文。中文本來的做法是斷句：用句號分成兩句、用分號承接對等的兩件事，或者整句換成「但」「不過」開頭——不會把整句用逗號焊住再插一個「而」續下去。這條抓的不是「而」這個字本身（「而且」「而是」「而非」都是正常中文的遞進或對比連接詞），抓的是「逗號＋而」這個焊接動作本身；單看一次不成立，一篇裡反覆這樣接句子，才是翻譯腔的訊號。

## Before（禁式）

```text
所有能分辨它們的東西都在被記錄的範圍之外,而其中三件是我的程式以外的東西可以改的。取樣參數從來不是我的程式送出去的,所以實際生效的值來自模型自己的設定檔,而同一個 tag 重拉一次就可能把它換掉。
```

英文對照（僅供理解，本條不檢查英文；這是上面那段中文在翻譯前可能長的樣子）：

```text
All the details that could tell the two runs apart lie outside the log, and three of them are things my program can't even touch. The sampling params were never sent by my code, so the value that actually took effect comes from the model's own config file, and pulling the same tag again could swap it out from under you.
```

## After（改法）

```text
能分辨的線索全都落在記錄範圍之外,其中三項還是我的程式管不到、別人改得動的。取樣參數根本不是我的程式送出去的,實際生效的值來自模型自己的設定檔;同一個 tag 重拉一次,就可能被換掉。
```

改法：把「逗號＋而」焊住的兩個子句拆開——第一句改成句號分句、主語各自成立（不再靠「而」續下去）；第二句改用分號承接同層的兩件事（設定檔來源／tag 重拉會被換掉），不再用「而」當連接詞。兩處都不是刪字，是換句法：中文本來就有斷句與分號可以做同一件事，不必靠「而」把兩句焊在一起。

英文對照（僅供理解，本條不檢查英文）：

```text
All the details that could tell the two runs apart lie outside the log. Three of them are things my program can't even touch. The sampling params were never sent by my code — the value that actually took effect comes from the model's own config file; pulling the same tag again could swap it out from under you.
```

出處：`williamlab-site/content/articles/decision-provenance.zh.mdx` 改前／改後兩版（0926 主 session 提供的校準組），Before 取自尚未去翻譯腔的版本，After 取自已去翻譯腔並與站上同步的版本，兩段對應同一段內容。

## 例外

- 「而且」「而是」「而非」「而不是」「而不只」「而不光」「而後」「而已」都不算，pattern 已排除，不需人判。前三個是正常中文的遞進或對比連接詞；「而不是」「而不只」「而不光」是同一個對比結構的否定形（「A，而不是 B」是道地中文，`B` 不是完整子句，沒有焊接發生），0926 首版漏排除，實測佔 18 篇正本全部命中的 22%（21／97，全語料 97 → 76）後補上；「而後」「而已」是時序連接詞與語氣詞，同樣不是焊接。
- 引用人物原話時保留原樣，加引號。
- 全篇僅出現一次不算違規，本條只抓全篇累積兩次以上的情況（比照 R-017 的「全篇 >= 2」寫法：偶爾一次是正常書面語的連接詞用法，反覆焊句子才是翻譯腔）。
- 成語或文言引語中的「而」（如「學而時習之」）不受影響：本條 pattern 要求逗號緊接在「而」之前，這類引語通常沒有逗號，不會誤觸。
- 其餘無例外。

## 機械檢查可行性

- 可機械化：中文匹配 `[,，]而(?!且)(?!是)(?!非)(?!不是)(?!不只)(?!不光)(?!後)(?!已)`（逗號或全形逗號緊接「而」，且「而」後不接「且」「是」「非」「不是」「不只」「不光」「後」「已」），全篇累積命中 >= 2 次才標記。
- **半形逗號的發現**：校準時發現本 repo 語料（decision-provenance 改前改後兩版＋ williamlab-site 18 篇正本）全數使用半形逗號 `,` 標句讀，一次全形「，」都沒有（`grep -c '，'` 全部為 0）；句號則相反，全部用全形「。」。pattern 的逗號字元類同時納入 `,` 與 `，`，避免只認全形逗號而在這批真實語料上失靈。這個發現也影響其他既有規則的 zh pattern（例如 R-009 的 `，` 假設），但不在本次任務範圍內，留給主 session 判斷是否要回頭補。
- 0926 首次實測校準：Before（decision-provenance 改前版）漢字 2824、命中 **18** 處、密度 6.37／千漢字；After（改後版）漢字 2769、命中 **0** 處、密度 0.00／千漢字——同一篇文章改前改後從 18 降到 0，是本條最乾淨的單篇對照。（首版 pattern 漏排除「而不是」時這裡是 22 → 0；扣掉那 4 處假陽性後仍是 18 → 0，對照不受影響。）
- 18 篇 williamlab-site 中文正本（decision-provenance.zh.mdx 目前站上內容經比對與 Before 逐字相同，見「疑點」，故此檔在下面的分布裡等同於 Before 本身，不是獨立的第三份樣本）：漢字 >= 500 的 15 篇裡，10 篇命中 >= 2（密度 1.37～6.37／千漢字，含 decision-provenance 本身 6.37），4 篇命中 1 次、1 篇 0 次不達門檻（`enterprise-ai-adoption-identity-gateway` 0.53、`enterprise-ai-adoption-reference-architecture` 0.60、`validating-organizational-legitimacy` 1.17、`change-intent-governance` 0.46、`why-code-gets-cheap` 0.00）；漢字 < 500 的 3 篇（`context-engineering-as-architecture.zh.mdx` 306 字、`designing-agent-runtime.zh.mdx` 411 字、`governance-driven-engineering.zh.mdx` 263 字）密度雜訊過大不列入判準，見下一條。
- 語料定義與長度下限：剝掉 frontmatter、fenced code block、inline code、Markdown 連結方括號後的正文；**全文漢字 >= 500 才計密度**，低於這個數字時單次命中就能把密度推到 7／千字以上（如 `governance-driven-engineering.zh.mdx` 263 字、2 次命中密度 7.60），也可能單純沒撞上而變成 0（`context-engineering-as-architecture.zh.mdx` 306 字、0 次命中），兩種雜訊在短文裡都無法跟真訊號分開，500 字是本次校準能穩定分出雙群的下限。
- 門檻落在雙峰之間的空隙：分界不是密度數字本身，而是**次數**。漢字 >= 500 的 15 篇裡，命中 0 或 1 次的有 5 篇（0.00～1.17／千漢字），2 次以上的有 10 篇（1.37～6.37／千漢字）；門檻定在「全篇 >= 2 次」，把「1 次、可能是正常書面語的連接詞用法」與「2 次以上、反覆焊句子」分開。**密度本身分不開這兩群**——兩群的邊界只差 1.17 對 1.37（`validating-organizational-legitimacy` 1 次 vs `accountable-generation` 3 次），密度幾乎連續；次數才是乾淨的分界，而且不受篇幅影響。這也是本條不寫密度門檻的理由。讓機械保守一點，寧可漏標，不把單次的正常用法當翻譯腔。
- 只能人審的部分：命中的兩句是否真的是把英文式對等子句焊在一起，還是恰好是「而」的合法遞進用法但沒被例外詞排除到（例如更少見的「而後」「而已」），需人判斷；全篇累積數達標後仍要看是否集中在同一種句型，還是分散在不同、各自成立的用法。
- **試過但放棄的候選**（附 0926 實測數字，理由同本節精神）：
  - `而且`：改前 n=4、改後 n=4，完全沒有差異，不是翻譯腔訊號。
  - `的[X]的`（`的X的` 嵌套，`X` 為 1–8 個非標點字）：改前密度 5.31／千字、改後 2.53／千字，方向對但 18 支正本裡有 3 篇（含短文）落在改後值以下、多篇落在改後值附近（2.17～2.8／千字），跟改後值重疊，切不出乾淨的門檻，剔除。
  - `被[XX]`（被動態）：改前 6.73／千字、改後 5.78／千字，差距小；18 支正本裡改後值（5.78）落在中段，甚至高於 10 篇正本，方向反了——這批中文正本本身被動態就偏多，不是翻譯腔特有訊號，剔除。
  - `一個[X]的`（冠詞直譯嫌疑）：改前 3.90／千字、改後 3.25／千字，18 支正本改後值一樣落在中段，跟被動態同樣的問題，剔除。
  - `的話`：改前 n=1、改後 n=0，18 支裡只有 3 篇命中且都是 n=1，樣本量太小（每篇最多 1 次），不足以校準門檻，剔除。
  - `其中`：改前 n=3、改後 n=3，無差異，剔除。
  - `進行[XX]`、`使得`、`對於`（句首）、`透過…來`、`當…時`：這五個候選在 Before、After、18 支正本裡全數命中 0 次（`當…時` 在 3 篇正本各命中 1 次，數字太小不成立），不是本作者語料裡會出現的翻譯腔形態，也可能是這位作者本來就不寫這類句子，不足以校準，剔除，不寫進機械 pattern。
  - 另外加測 4 個候選（`不僅…而且`、`在…中`、`值得注意的是`、`可以看出／可以發現`、`需要指出的是`、`一定程度上`、`換句話說`、`不可否認`）：除了「在…中」有零星 1 次命中（改前改後密度幾乎相同，0.35 對 0.36），其餘全部 0 次，同樣不成立，剔除。這批候選多半是正式論說文的翻譯腔（「值得注意的是」一類），這位作者的技術部落格語域用不到，值得記錄但不代表這些形態在別的語料裡也不成立——只是這批校準組測不出來。

## 適用 profile

- `articles`：嚴格。
- `narration`：嚴格。理由：「逗號＋而」是書面語才有的子句焊接手法，口語敘述本來就會把長句拆成短句、靠語氣停頓分句，不會用「而」去接兩個完整子句；口播稿裡出現這個形態，比在文章裡更不自然，沒有放寬的理由。
