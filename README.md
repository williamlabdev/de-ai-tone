# de-ai-tone

家規品質檢查，不是躲檢測工具。

這組規則用來檢查中英文行銷稿件是否寫得像人，不是用來騙過 AI 檢測器。
凡是為了「讓分數降低」而改寫、不顧語意與事實的，一律不做。

「像人」在這裡只有一個正向判準，就是每段至少一個可驗證資訊（數字、時間、人名、動作）。
`rules/` 裡的 12 條全是負向禁式，只擋空轉的句型，不能替稿子生出內容；寫不出資訊就標 `[待補]`，不用氣勢補。

本 repo 只放規則與流程。定調語料是個人的，不進這裡；writer 起草前讀的語料檔由寫稿單或稿件檔頭指定路徑。
英文 pattern 已寫進每條規則的 frontmatter。0922 第一支英文旁白稿實測（約 970 words）命中 1 處，同時修了 4 條 pattern；0925 第二支英文稿（約 2430 words）機械僅 R-008×1＋R-009×4（全人判放行）；同日 4 支外部稿誤殺評估中文 precision 約 88%（22/25，誤殺皆功能名詞類），英文外部僅中 2 筆且全放行。英文樣本仍少，結果先當提示不當結論。

用法三行：

1. 稿件檔頭註明 `tone-version`，值抄本 repo 的 `VERSION`（現為 `0.2.5`）。
2. 起草時載入 `prompts/style-constraints.md`，完稿後對 `rules/` 逐條自查。
3. 新增禁式時先抄 `rules/_template.md`，一條一檔，編號遞增。

目錄說明：`rules/` 是禁式本體，`profiles/` 是場景開關，
`prompts/` 是起草用約束片段，`examples/` 是 public-safe 例句，
`tools/` 說明哪些檢查可機械化、哪些只能人審。
